## 一、实验概述

### 1.1 实验名称

拆开计算机的大脑——基于 RISC-V 体系结构的 Mini 教学计算机设计与「x = 1 + 2」完整执行过程模拟

### 1.2 实验目标

通过亲手设计并实现一个基于 **RISC-V 开源指令集架构**的简化教学计算机模拟器，以 **`x = 1 + 2`** 这条最简单的加法指令为贯穿始终的实例，完整走通以下链路，建立对计算机硬件工作原理的系统性认知：

```
高级语言 x = 1 + 2
    ↓ 编译
汇编语言 addi / add
    ↓ 汇编
二进制机器码 0x1A000100 ...
    ↓ 存储到内存
内存地址空间中的指令与数据
    ↓ 取指
指令寄存器 IR 中的 32 位
    ↓ 译码
操作码 + 操作数 → 控制信号
    ↓ 按时钟节拍执行
取操作数 → ALU 运算 → 写回结果
```

### 1.3 实验设计的整体思维

#### 为什么要做这个实验？

当你在 Python 里写下 `x = 1 + 2` 并得到 3 时，你可能觉得这是理所当然的。但计算机内部到底发生了什么？这个 3 是怎么算出来的？

对于只学过高级语言的学生来说，"指令执行"是一个黑盒。本实验的目的，就是让你亲手**拆开这个黑盒**，看到里面的每一个零件是如何协同工作的。

#### 这个实验培养什么样的思维模式？

1. **分层抽象思维**：从高级语言 → 汇编 → 机器码 → 硬件电路，每一层都是对上一层的抽象。学会在不同抽象层次之间切换，理解每一层做了什么、为什么这样做。

2. **自底向上的系统思维**：从最底层的二进制位开始，一步步构建出寄存器、ALU、内存、控制器，最终组成一台能执行程序的计算机。理解系统是如何由简单部件组合出复杂功能的。

3. **时序思维**：计算机的所有操作都由时钟驱动，按时钟节拍一步步执行。学会用"周期 1 做什么、周期 2 做什么"的方式思考问题，理解同步数字系统的工作方式。

4. **状态机思维**：CPU 的执行过程本质上是一个状态机——取指状态、译码状态、执行状态，每个状态下寄存器和内存的值都在变化。学会跟踪系统状态的变化。

#### 这个实验帮助你建立什么样的认知系统？

- **对"程序"的认知**：程序不只是高级语言代码，它最终是内存中的一串 0 和 1。指令和数据在内存中没有本质区别，区别只在于 CPU 怎么解释它们。
- **对"CPU"的认知**：CPU 不是一个神秘的黑盒，它由寄存器堆、ALU、控制器（取指/译码/执行）组成，每一部分的功能都是明确的。
- **对"指令执行"的认知**：一条指令的执行不是瞬间完成的，它需要多个时钟周期，经历取指、译码、执行等阶段，每个阶段都有明确的数据通路。
- **对"RISC-V 设计哲学"的认知**：理解为什么 RISC-V 要设计成固定长度指令、Load-Store 架构、r0 恒为 0、无标志寄存器——这些设计选择背后都有深刻的工程考量。

### 2.1 从「算盘解题」到「存储程序」

#### 2.1.1 用算盘计算 a + b = y

在计算机诞生之前，人们用算盘计算。假设要计算 a + b = y（a=1, b=2）：

```
┌─────────────────────────────────────────────────────────────┐
│                    纸（存储介质）                              │
├──────┬──────────────────────────────────┬───────────────────┤
│ 行号 │ 解题步骤（程序）                   │ 说明              │
├──────┼──────────────────────────────────┼───────────────────┤
│  1   │ 取数第7行数据 → 算盘              │ 取数据 a=1        │
│  2   │ 加第8行数据 → 算盘                │ 完成 a+b，结果在算盘│
│  3   │ 存结果数据 → 第9行                │ 把 y=3 记到第9行   │
│  4   │ 输出                              │ 把结果写在纸上      │
│  5   │ 停止                              │ 运算完毕            │
│  6   │                                  │                   │
│  7   │ a = 1                            │ 参加运算的数据      │
│  8   │ b = 2                            │ 参加运算的数据      │
│  9   │ y = ?                            │ 计算结果数据        │
└──────┴──────────────────────────────────┴───────────────────┘
```

**关键观察**：
1. **数据和解题步骤都存在同一张纸上**——这就是"存储程序"思想的雏形
2. **解题步骤（程序）和数据都是纸上的符号**——它们在存储介质上没有本质区别
3. **每一步操作都需要人来执行**——人就是"控制器+运算器"

#### 2.1.2 冯·诺依曼的存储程序思想

1945 年，冯·诺依曼提出了"**存储程序**"（Stored Program）的计算机设计思想：

> **程序和数据都以二进制形式存储在同一个存储器中，CPU 从存储器中自动取出指令并执行。**

这一思想的核心是：**指令也是数据**。在内存里，指令和数据都是 0 和 1，区别只在于 CPU 怎么解释它们——从 PC 指向的地址取出来就解释为指令，从 lw/sw 的地址取出来就解释为数据。

本实验中，你会亲手把 `x = 1 + 2` 的汇编程序翻译成机器码，存到内存里，然后让 CPU 从内存里一条一条取出来执行。

#### 2.1.3 冯·诺依曼计算机的五大组成部分

```
┌─────────────────────────────────────────────────────────────┐
│                      控制器 (CU)                               │
│         指挥协调各部件工作，产生执行指令的控制信号              │
└──────────────┬──────────────────────────┬───────────────────┘
               │                          │
┌──────────────▼──────────┐  ┌───────────▼──────────┐
│      运算器 (ALU)         │  │      存储器 (Memory)   │
│   算术运算 + 逻辑运算      │  │   存储程序和数据         │
│   累加器、通用寄存器       │  │   按地址访问             │
└──────────────┬──────────┘  └───────────┬──────────┘
               │                          │
┌──────────────▼──────────────────────────▼──────────┐
│           输入设备 (Input) / 输出设备 (Output)        │
│         键盘/鼠标/传感器  /  显示器/打印机/执行器     │
└───────────────────────────────────────────────────────┘
```

| 部件 | 英文 | 功能 | 本实验中的实现 |
|------|------|------|--------------|
| 运算器 | ALU | 执行算术和逻辑运算 | add / sub / and / or / slt |
| 控制器 | CU | 取指、译码、产生控制信号 | fetch / decode / execute 三阶段 |
| 存储器 | Memory | 存储程序和数据 | 1024 字节内存，按字节寻址，小端序 |
| 输入设备 | Input | 接收外部数据 | （简化，通过立即数模拟） |
| 输出设备 | Output | 输出处理结果 | ecall 系统调用（print_int） |

**CPU = 运算器 + 控制器**。本实验中，你要用 Python 模拟的就是：内存 + 寄存器 + ALU + 控制器（取指译码执行）。

### 2.2 从 `x = 1 + 2` 到汇编语言

#### 2.2.1 高级语言的含义

```python
x = 1 + 2
```

这条语句的含义是：
1. 把立即数 1 放到某个存储位置（变量 x 的临时位置）
2. 把立即数 2 放到另一个存储位置
3. 对这两个数做加法
4. 把结果 3 存到变量 x 中

在 CPU 层面，"存储位置"就是**寄存器**（CPU 内部的高速存储单元）。RISC-V 是 **Load-Store 架构**：运算指令只能操作寄存器，不能直接操作内存。所以 `x = 1 + 2` 需要先把立即数加载到寄存器，再在寄存器间做加法。

#### 2.2.2 对应的汇编代码

```asm
# x = 1 + 2
# 寄存器分配：t0 存 1，t1 存 2，t2 存结果 3
        li   t0, 1        # t0 = 1（加载立即数 1 到 t0）
        li   t1, 2        # t1 = 2（加载立即数 2 到 t1）
        add  t2, t0, t1   # t2 = t0 + t1 = 1 + 2 = 3
```

**逐条解释**：

| 汇编指令 | 伪指令展开 | 含义 |
|---------|-----------|------|
| `li t0, 1` | `addi t0, zero, 1` | 把立即数 1 加到 zero 寄存器（恒为 0），结果存入 t0。即 t0 = 0 + 1 = 1 |
| `li t1, 2` | `addi t1, zero, 2` | 同理，t1 = 0 + 2 = 2 |
| `add t2, t0, t1` | （真实指令） | t2 = t0 + t1 = 1 + 2 = 3 |

**`li` 是伪指令**（Pseudoinstruction），不是独立的硬件指令。汇编器会把它翻译成 `addi rd, zero, imm`。这利用了 RISC-V 的经典设计——**r0（zero）恒为 0**：用一个恒为 0 的寄存器，就可以用 `addi` 实现"加载立即数"，不需要单独设计一条 `li` 指令。

#### 2.2.3 本教学机的寄存器约定

本教学机简化为 8 个通用寄存器（真实 RISC-V 有 32 个），用 3 位二进制编码：

| 编号 | 二进制 | ABI 名称 | 用途 | 特殊之处 |
|------|--------|---------|------|---------|
| r0 | 000 | zero | 恒为 0 | 硬连线为 0，读返回 0，写忽略 |
| r1 | 001 | ra | 返回地址 | 函数调用时保存返回地址 |
| r2 | 010 | a0 | 参数/返回值/输出 | 系统调用的参数和返回值 |
| r3 | 011 | a7 | 系统调用号 | ecall 时指定调用类型 |
| r4 | 100 | t0 | 临时寄存器 | 本实验中存 1 |
| r5 | 101 | t1 | 临时寄存器 | 本实验中存 2 |
| r6 | 110 | t2 | 临时寄存器 | 本实验中存结果 3 |
| r7 | 111 | t3 | 临时寄存器 | 备用 |

还有一个特殊寄存器：
- **PC（Program Counter，程序计数器）**：存放下一条要执行的指令的地址，每次取指后自动 +4

### 2.3 从汇编到机器码——指令的二进制编码

#### 2.3.1 指令的结构

一条指令由两部分组成：

```
┌──────────────────────────────────────────────────────┐
│                      32 位指令                          │
├──────────────────────────┬───────────────────────────┤
│       操作码（Opcode）     │      操作数（Operand）      │
│    规定要做什么操作         │   规定对哪些数据做操作       │
└──────────────────────────┴───────────────────────────┘
```

- **操作码（Opcode）**：唯一标识指令类型（加法、加载、存储、跳转等）
- **操作数（Operand）**：指定操作涉及的寄存器编号或立即数

#### 2.3.2 RISC-V 的指令格式设计思想

RISC-V 的指令格式设计遵循一个核心原则：**字段位置固定**。

所有指令的 **opcode 都在最低 7 位**（bit[6:0]），所有格式的 **rd 都在 bit[11:7]**，**rs1 都在 bit[19:15]**，**rs2 都在 bit[24:20]**。

这种设计大大简化了硬件译码电路——译码器不需要先判断指令类型再去不同位置找字段，而是直接从固定位置读取 rd、rs1、rs2，然后根据 opcode 判断怎么用这些字段。

#### 2.3.3 本教学机的四种指令格式

本教学机为了降低难度，将 RISC-V 标准的 6 种格式简化为 4 种（寄存器从 5 位缩减为 3 位，opcode 从 7 位缩减为 6 位）：

**R 型（寄存器-寄存器运算）**：add, sub, and, or, slt
```
┌──────────────────────────────────────────────────────────────────┐
│ bit[31:26]  │ bit[25:23] │ bit[22:20] │ bit[19:17] │ bit[16:0] │
│  opcode(6)   │    rd(3)    │   rs1(3)    │   rs2(3)    │  保留(17)  │
└──────────────────────────────────────────────────────────────────┘
```

**I 型（立即数运算 + 加载 + 系统调用）**：addi, lw, jalr, ecall
```
┌──────────────────────────────────────────────────────────────────┐
│ bit[31:26]  │ bit[25:23] │ bit[22:20] │  bit[19:8]   │ bit[7:0]  │
│  opcode(6)   │    rd(3)    │   rs1(3)    │   imm(12)     │  保留(8)   │
└──────────────────────────────────────────────────────────────────┘
```

**S 型（存储 + 分支）**：sw, beq, bne
```
┌──────────────────────────────────────────────────────────────────┐
│ bit[31:26]  │ bit[25:23] │ bit[22:20] │  bit[19:8]   │ bit[7:0]  │
│  opcode(6)   │   rs2(3)    │   rs1(3)    │   imm(12)     │  保留(8)   │
└──────────────────────────────────────────────────────────────────┘
```

**J 型（跳转 + 高位立即数）**：jal, lui
```
┌──────────────────────────────────────────────────────────────────┐
│ bit[31:26]  │ bit[25:23] │        bit[22:3]         │ bit[2:0]  │
│  opcode(6)   │    rd(3)    │        imm(20)           │  保留(3)   │
└──────────────────────────────────────────────────────────────────┘
```

字段说明：
- **opcode（6 位）**：操作码，唯一标识指令类型
- **rd（3 位）**：目标寄存器编号（0-7），指令执行结果写入此寄存器
- **rs1（3 位）**：源寄存器 1 编号
- **rs2（3 位）**：源寄存器 2 编号
- **imm（12/20 位）**：立即数，I/S 型为 12 位有符号数，J 型为 20 位有符号数

#### 2.3.4 本教学机的指令操作码表

| 类型 | 指令 | opcode（十进制） | opcode（二进制） | 格式 | 功能 |
|------|------|-----------------|-----------------|------|------|
| R 型 | add | 1 | 000001 | R | rd = rs1 + rs2 |
| R 型 | sub | 2 | 000010 | R | rd = rs1 - rs2 |
| R 型 | and | 3 | 000011 | R | rd = rs1 & rs2 |
| R 型 | or | 4 | 000100 | R | rd = rs1 \| rs2 |
| R 型 | slt | 5 | 000101 | R | rd = (rs1 < rs2) ? 1 : 0 |
| I 型 | addi | 6 | 000110 | I | rd = rs1 + imm |
| I 型 | lw | 7 | 000111 | I | rd = memory[rs1 + imm] |
| I 型 | jalr | 8 | 001000 | I | rd = PC+4; PC = rs1 + imm |
| I 型 | ecall | 9 | 001001 | I | 系统调用（a7=调用号） |
| S 型 | sw | 10 | 001010 | S | memory[rs1 + imm] = rs2 |
| S 型 | beq | 11 | 001011 | S | if(rs1 == rs2) PC += imm |
| S 型 | bne | 12 | 001100 | S | if(rs1 != rs2) PC += imm |
| J 型 | jal | 13 | 001101 | J | rd = PC+4; PC += imm |
| J 型 | lui | 14 | 001110 | J | rd = imm << 12 |

#### 2.3.5 实例：`addi t0, 1` 的编码过程

以第一条指令 `addi t0, 1`（即 `addi r4, r0, 1`）为例，逐步编码：

**第一步：确定指令格式和字段值**
- 指令：addi → I 型格式，opcode = 6 = 000110
- rd = t0 = r4 = 100
- rs1 = zero = r0 = 000
- imm = 1 = 000000000001（12 位）
- 保留 = 00000000（8 位）

**第二步：按格式拼接**

```
I 型格式: opcode(6) | rd(3) | rs1(3) | imm(12) | 保留(8)

填入:     000110    |  100   |  000    | 000000000001 | 00000000
```

**第三步：合并为 32 位二进制**

```
000110 100 000 000000000001 00000000
= 00011010000000000000000100000000
```

**第四步：转换为十六进制**

从右往左每 4 位分组：
```
0001 1010 0000 0000 0000 0001 0000 0000
 1    A    0    0    0    1    0    0
= 0x1A000100
```

所以 `addi t0, 1` 的机器码是 **`0x1A000100`**。

#### 2.3.6 三条指令的完整编码

| 汇编指令 | 展开 | opcode | rd | rs1 | rs2/imm | 机器码（十六进制） |
|---------|------|--------|-----|-----|---------|-------------------|
| `li t0, 1` | `addi r4, r0, 1` | 000110 | 100(r4) | 000(r0) | imm=000000000001 | `0x1A000100` |
| `li t1, 2` | `addi r5, r0, 2` | 000110 | 101(r5) | 000(r0) | imm=000000000010 | `0x1A800200` |
| `add t2, t0, t1` | `add r6, r4, r5` | 000001 | 110(r6) | 100(r4) | rs2=101(r5) | `0x074A0000` |

**`add t2, t0, t1` 的编码验证**：
```
R 型格式: opcode(6) | rd(3) | rs1(3) | rs2(3) | 保留(17)
填入:     000001    |  110   |  100   |  101   | 00000000000000000

合并: 00000111010010100000000000000000
分组: 0000 0111 0100 1010 0000 0000 0000 0000
     = 0x074A0000  ✓
```

### 2.4 机器码在内存中的存储——内存地址空间

#### 2.4.1 内存的抽象模型

内存可以想象成一个巨大的**字节数组**，每个字节（8 位）有一个唯一的地址（门牌号）：

```
┌─────────────────────────────────────────────────────────────────┐
│                        内存（Memory）                              │
│                  1024 字节（本教学机）                             │
├──────────┬──────────────────────────────────────────────────────┤
│  地址     │                    内容（1 字节 = 8 位）              │
├──────────┼──────────────────────────────────────────────────────┤
│  0x0000  │  ┌──┬──┬──┬──┬──┬──┬──┬──┐                         │
│          │  │b7│b6│b5│b4│b3│b2│b1│b0│  ← 8 个二进制位          │
│  0x0001  │  └──┴──┴──┴──┴──┴──┴──┴──┘                         │
│  0x0002  │  ...                                                   │
│  0x0003  │  ...                                                   │
│   ...    │  ...                                                   │
│  0x03FF  │  （最后一个字节）                                      │
└──────────┴──────────────────────────────────────────────────────┘
```

关键概念：
- **位（bit）**：计算机中最小的信息单位，一个二进制位（0 或 1）
- **字节（byte）**：8 个二进制位 = 1 字节，是内存寻址的基本单位
- **字（word）**：CPU 一次处理的数据量，本教学机是 32 位 = 4 字节
- **地址（address）**：每个字节的唯一编号，本教学机用十六进制表示（0x0000 ~ 0x03FF）
- **存储容量**：内存的总字节数，本教学机 1024 字节 = 1KB

#### 2.4.2 小端序（Little-Endian）

一个 32 位的指令（4 字节）存在内存中，有两种存放方式：

**大端序（Big-Endian）**：高字节存在低地址
```
地址:   0x0000  0x0001  0x0002  0x0003
内容:   0x1A    0x00    0x01    0x00    ← 高字节在前
```

**小端序（Little-Endian）**：低字节存在低地址
```
地址:   0x0000  0x0001  0x0002  0x0003
内容:   0x00    0x01    0x00    0x1A    ← 低字节在前
```

本教学机采用**小端序**（与 x86、RISC-V 默认一致）。小端序的好处是：类型转换时不需要改变地址（比如把 32 位整数转成 8 位，直接读低地址就行）。

#### 2.4.3 x = 1 + 2 程序在内存中的完整布局

三条指令从地址 0x0000 开始存放，每条指令 4 字节：

```
┌──────────────────────────────────────────────────────────────────────────┐
│                              内存地址空间                                    │
├──────────┬────────┬────────┬────────┬────────┬───────────────────────────┤
│  地址     │ 字节0  │ 字节1  │ 字节2  │ 字节3  │      说明                 │
│ (十六进制) │(低地址)│        │        │(高地址) │                           │
├──────────┼────────┼────────┼────────┼────────┼───────────────────────────┤
│  0x0000  │  0x00  │  0x01  │  0x00  │  0x1A  │ addi r4, r0, 1 (t0=1)   │
│          │(00000000│00000001│00000000│00011010│ 机器码 0x1A000100       │
│          │ 低字节) │        │        │ 高字节) │ (小端序: 低字节在低地址)  │
├──────────┼────────┼────────┼────────┼────────┼───────────────────────────┤
│  0x0004  │  0x00  │  0x02  │  0x00  │  0x1A  │ addi r5, r0, 2 (t1=2)   │
│          │        │        │        │        │ 机器码 0x1A800200       │
├──────────┼────────┼────────┼────────┼────────┼───────────────────────────┤
│  0x0008  │  0x00  │  0x00  │  0x4A  │  0x07  │ add r6, r4, r5 (t2=t0+t1)│
│          │        │        │        │        │ 机器码 0x074A0000       │
├──────────┼────────┼────────┼────────┼────────┼───────────────────────────┤
│  0x000C  │  0x00  │  0x00  │  0x00  │  0x00  │ （空闲，未使用）           │
│   ...    │  ...   │  ...   │  ...   │  ...   │                           │
│  0x03FC  │  0x00  │  0x00  │  0x00  │  0x00  │ （内存末尾）               │
└──────────┴────────┴────────┴────────┴────────┴───────────────────────────┘
```

**重点观察**：
1. **指令和数据在内存中没有区别**——都是 0 和 1。CPU 从 PC 指向的地址（0x0000）取出来，就解释为指令
2. **每条指令占 4 字节**，所以 PC 每次 +4（0x0000 → 0x0004 → 0x0008）
3. **小端序**：以第一条指令 0x1A000100 为例，最低字节 0x00 存在最低地址 0x0000，最高字节 0x1A 存在最高地址 0x0003
4. **地址是字节地址**：0x0000、0x0001、0x0002... 每个地址对应 1 个字节。读一个 32 位字需要读 4 个连续字节

#### 2.4.4 从内存读取一条 32 位指令的过程

以读取地址 0x0000 的指令为例：

```
┌─────────────────────────────────────────────────────────────────┐
│  步骤1: CPU 将 PC=0x0000 放到地址总线上                           │
│         ↓                                                         │
│  步骤2: 内存根据地址 0x0000，读出 4 个连续字节:                  │
│         内存[0x0000] = 0x00  (字节0, 最低字节)                   │
│         内存[0x0001] = 0x01  (字节1)                            │
│         内存[0x0002] = 0x00  (字节2)                            │
│         内存[0x0003] = 0x1A  (字节3, 最高字节)                   │
│         ↓                                                         │
│  步骤3: 按小端序合并为 32 位:                                     │
│         指令 = (字节3<<24) | (字节2<<16) | (字节1<<8) | 字节0   │
│              = (0x1A<<24) | (0x00<<16) | (0x01<<8) | 0x00      │
│              = 0x1A000100                                         │
│         ↓                                                         │
│  步骤4: 通过数据总线送回 CPU，存入指令寄存器 IR                    │
└─────────────────────────────────────────────────────────────────┘
```

### 2.5 指令寄存器（IR）——32 位指令的暂存与字段拆分

#### 2.5.1 指令寄存器的作用

**指令寄存器（Instruction Register, IR）**是控制器中的一个专用寄存器，用于暂存当前正在执行的指令。

为什么需要 IR？因为从内存读出的指令是一个 32 位的二进制数，CPU 需要把它拆开，分别取出操作码、目标寄存器、源寄存器、立即数等字段，然后才能译码和执行。IR 就是这个"拆解工作台"。

#### 2.5.2 add 指令在 IR 中的放置

以第三条指令 `add t2, t0, t1`（机器码 `0x074A0000`）为例，看它在 IR 中是怎么放置的：

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                     指令寄存器 IR（32 位）                                      │
├──────┬──────┬──────┬──────┬──────┬──────┬──────┬──────┬──────┬──────┬──────┤
│ b31  │ b30  │ b29  │ b28  │ b27  │ b26  │ b25  │ b24  │ b23  │ b22  │ ...  │
│  0   │  0   │  0   │  0   │  0   │  1   │  1   │  1   │  0   │  1   │ ...  │
└──────┴──────┴──────┴──────┴──────┴──────┴──────┴──────┴──────┴──────┴──────┘

按 R 型格式拆分字段:

┌──────────────────────────────────────────────────────────────────────────────┐
│ bit[31:26]  │ bit[25:23] │ bit[22:20] │ bit[19:17] │      bit[16:0]       │
│  opcode(6)   │    rd(3)    │   rs1(3)    │   rs2(3)    │      保留(17)        │
├──────────────┼─────────────┼─────────────┼─────────────┼──────────────────────┤
│   000001     │     110     │     100     │     101     │  00000000000000000   │
│   = 1 (add)  │   = r6(t2)  │  = r4(t0)   │  = r5(t1)   │                      │
└──────────────┴─────────────┴─────────────┴─────────────┴──────────────────────┘
```

**字段提取方法**（用位运算从 32 位指令中提取各字段）：

```python
opcode = (instr >> 26) & 0x3F    # 右移26位，取低6位 → 000001 = 1
rd     = (instr >> 23) & 0x07    # 右移23位，取低3位 → 110 = 6 (r6)
rs1    = (instr >> 20) & 0x07    # 右移20位，取低3位 → 100 = 4 (r4)
rs2    = (instr >> 17) & 0x07    # 右移17位，取低3位 → 101 = 5 (r5)
```

验证：
```
instr = 0x074A0000 = 0000 0111 0100 1010 0000 0000 0000 0000

opcode = (0x074A0000 >> 26) & 0x3F
       = 000001 & 0x3F = 1  ✓ (add)

rd = (0x074A0000 >> 23) & 0x07
   = 110 & 0x07 = 6  ✓ (r6 = t2)

rs1 = (0x074A0000 >> 20) & 0x07
    = 100 & 0x07 = 4  ✓ (r4 = t0)

rs2 = (0x074A0000 >> 17) & 0x07
    = 101 & 0x07 = 5  ✓ (r5 = t1)
```

#### 2.5.3 I 型指令在 IR 中的字段拆分

以 `addi t0, 1`（机器码 `0x1A000100`）为例：

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ bit[31:26]  │ bit[25:23] │ bit[22:20] │      bit[19:8]      │  bit[7:0]   │
│  opcode(6)   │    rd(3)    │   rs1(3)    │      imm(12)        │   保留(8)    │
├──────────────┼─────────────┼─────────────┼─────────────────────┼──────────────┤
│   000110     │     100     │     000     │   000000000001      │  00000000    │
│   = 6 (addi) │  = r4(t0)   │  = r0(zero) │      = 1            │              │
└──────────────┴─────────────┴─────────────┴─────────────────────┴──────────────┘
```

立即数提取：
```python
imm = (instr >> 8) & 0xFFF     # 右移8位，取低12位
    = 000000000001 = 1  ✓
```

### 2.6 指令译码——从操作码到控制信号

#### 2.6.1 译码器的工作原理

**指令译码器（Instruction Decoder, ID）**是控制器的核心部件，它的工作是：

1. 从 IR 中读取操作码（opcode）
2. 根据操作码判断是什么指令
3. 产生对应的**控制信号**（Control Signals），告诉 ALU、寄存器堆、内存等部件该做什么

```
┌──────────┐     opcode      ┌──────────────┐     控制信号      ┌─────────┐
│   IR     │ ──────────────→ │   译码器 ID   │ ──────────────→ │  ALU    │
│ (32位指令)│                 │              │ ──────────────→ │ 寄存器堆  │
└──────────┘                 └──────────────┘ ──────────────→ │  内存    │
```

#### 2.6.2 add 指令的译码过程

以 `add t2, t0, t1` 为例，译码器的工作：

```
输入: opcode = 000001 (1)

译码器查操作码表:
  000001 → ADD 指令

产生控制信号:
  ┌─────────────────────────────────────────────────┐
  │  控制信号          │ 值  │ 含义                   │
  ├────────────────────┼────┼────────────────────────┤
  │ ALU_op             │ ADD│ ALU 执行加法运算        │
  │ ALU_src1           │ rs1│ ALU 第一个操作数来自 rs1 │
  │ ALU_src2           │ rs2│ ALU 第二个操作数来自 rs2 │
  │ reg_write          │ 1  │ 将结果写入目标寄存器 rd   │
  │ reg_write_dst      │ rd │ 写入 rd 指定的寄存器     │
  │ mem_read           │ 0  │ 不读内存                 │
  │ mem_write          │ 0  │ 不写内存                 │
  │ branch             │ 0  │ 不是分支指令             │
  │ jump               │ 0  │ 不是跳转指令             │
  └────────────────────┴────┴────────────────────────┘
```

#### 2.6.3 addi 指令的译码过程

以 `addi t0, 1` 为例：

```
输入: opcode = 000110 (6)

译码器查操作码表:
  000110 → ADDI 指令（立即数加法）

产生控制信号:
  ┌─────────────────────────────────────────────────┐
  │  控制信号          │ 值  │ 含义                   │
  ├────────────────────┼────┼────────────────────────┤
  │ ALU_op             │ ADD│ ALU 执行加法运算        │
  │ ALU_src1           │ rs1│ ALU 第一个操作数来自 rs1 │
  │ ALU_src2           │ imm│ ALU 第二个操作数来自立即数│
  │ reg_write          │ 1  │ 将结果写入目标寄存器 rd   │
  │ reg_write_dst      │ rd │ 写入 rd 指定的寄存器     │
  │ mem_read           │ 0  │ 不读内存                 │
  │ mem_write          │ 0  │ 不写内存                 │
  └────────────────────┴────┴────────────────────────┘
```

**add 和 addi 的唯一区别**：add 的第二个操作数来自 rs2 寄存器，addi 的第二个操作数来自指令中的立即数 imm。

### 2.7 按时钟节拍执行——add 指令的完整执行流程

#### 2.7.1 时钟与时钟周期

CPU 的所有操作都由**时钟（Clock）**驱动。时钟是一个周期性的方波信号：

```
     ┌────┐    ┌────┐    ┌────┐
     │    │    │    │    │    │
─────┘    └────┘    └────┘    └────
     ← 一个时钟周期 →
```

- **时钟周期（Clock Cycle）**：时钟信号从一次上升沿到下一次上升沿的时间
- **时钟频率（Clock Frequency）**：每秒的时钟周期数，单位 Hz（MHz、GHz）
- 在一个时钟周期内，CPU 完成一个基本操作（如取指、译码、执行）

本教学机采用**串行执行**（无流水线），每条指令需要 2 个时钟周期：
- 周期 1：取指（Fetch）
- 周期 2：译码 + 执行（Decode + Execute）

#### 2.7.2 指令执行的三阶段总览

```
┌──────────────────────────────────────────────────────────────────────────┐
│                        一条指令的执行过程                                    │
│                                                                          │
│  ┌──────────┐    ┌──────────┐    ┌──────────────────────────────────┐   │
│  │  取指     │ →  │  译码     │ →  │            执行                  │   │
│  │  Fetch   │    │  Decode  │    │          Execute                 │   │
│  └──────────┘    └──────────┘    └──────────────────────────────────┘   │
│       │               │                        │                           │
│  从内存取指令      分析操作码             ALU运算/访存/跳转                │
│  存入IR           产生控制信号            结果写回寄存器                    │
│  PC = PC + 4      提取操作数地址                                           │
└──────────────────────────────────────────────────────────────────────────┘
```

#### 2.7.3 实例：`add t2, t0, t1` 的逐节拍执行

假设当前状态：
- PC = 0x0008（指向 add 指令）
- t0(r4) = 1（前两条指令已执行完）
- t1(r5) = 2
- t2(r6) = 0（初始值）

**时钟周期 1：取指（Fetch）**

```
┌─────────────────────────────────────────────────────────────────────┐
│ 节拍 T1: 取指                                                         │
│                                                                     │
│  ① CPU 将 PC = 0x0008 放到地址总线上                                │
│         ↓                                                           │
│  ② 内存根据地址 0x0008 读出 4 字节:                                 │
│     内存[0x0008]=0x00, [0x0009]=0x00, [0x000A]=0x4A, [0x000B]=0x07│
│         ↓                                                           │
│  ③ 按小端序合并: 0x074A0000                                        │
│         ↓                                                           │
│  ④ 通过数据总线送回 CPU，存入指令寄存器 IR                           │
│     IR = 0x074A0000                                                │
│         ↓                                                           │
│  ⑤ PC 自动加 4: PC = 0x0008 + 4 = 0x000C（指向下一条指令）        │
│                                                                     │
│  本周期结束时状态:                                                   │
│    IR = 0x074A0000 (add r6, r4, r5)                               │
│    PC = 0x000C                                                      │
│    t0=1, t1=2, t2=0（尚未变化）                                     │
└─────────────────────────────────────────────────────────────────────┘
```

**时钟周期 2：译码（Decode）+ 执行（Execute）**

```
┌─────────────────────────────────────────────────────────────────────┐
│ 节拍 T2: 译码 + 执行                                                  │
│                                                                     │
│ 【译码阶段】                                                         │
│  ① 从 IR 提取字段:                                                  │
│     opcode = (IR >> 26) & 0x3F = 000001 = 1 (ADD)               │
│     rd     = (IR >> 23) & 0x07 = 110 = 6 (r6 = t2)              │
│     rs1    = (IR >> 20) & 0x07 = 100 = 4 (r4 = t0)              │
│     rs2    = (IR >> 17) & 0x07 = 101 = 5 (r5 = t1)              │
│         ↓                                                           │
│  ② 译码器查 opcode=1 → ADD 指令，产生控制信号:                      │
│     ALU_op=ADD, ALU_src1=rs1, ALU_src2=rs2, reg_write=1          │
│                                                                     │
│ 【执行阶段】                                                         │
│  ③ 从寄存器堆读取源操作数:                                           │
│     操作数 A = regs[rs1] = regs[4] = t0 = 1                      │
│     操作数 B = regs[rs2] = regs[5] = t1 = 2                      │
│         ↓                                                           │
│  ④ ALU 执行加法:                                                    │
│     结果 = A + B = 1 + 2 = 3                                       │
│         ↓                                                           │
│  ⑤ 将结果写入目标寄存器:                                             │
│     regs[rd] = regs[6] = t2 = 3                                    │
│     （reg_write=1 控制信号允许写入）                                 │
│                                                                     │
│  本周期结束时状态:                                                   │
│    t0=1, t1=2, t2=3  ✓ 加法完成！                                   │
│    PC = 0x000C（准备取下一条指令）                                   │
└─────────────────────────────────────────────────────────────────────┘
```

#### 2.7.4 三条指令的完整执行时序图

```
时间 →   周期1    周期2    周期3    周期4    周期5    周期6
         │        │        │        │        │        │
指令1    │ 取指   │ 译码执行│        │        │        │
(addi t0,1)│ 0x1A000100│ t0=1   │        │        │        │
         │        │        │        │        │        │
指令2    │        │        │ 取指   │ 译码执行│        │
(addi t1,2)│        │        │ 0x1A800200│ t1=2   │        │
         │        │        │        │        │        │
指令3    │        │        │        │        │ 取指   │ 译码执行
(add t2,t0,t1)│        │        │        │        │ 0x074A0000│ t2=3
         │        │        │        │        │        │
PC值:    0x0000→  0x0004   0x0004→  0x0008   0x0008→  0x000C
```

**总统计**：
- 指令数：3 条
- 时钟周期数：6 个
- CPI（每条指令周期数）= 6 / 3 = 2.0

#### 2.7.5 执行过程中的数据通路图

```
┌──────────────────────────────────────────────────────────────────────────┐
│                           CPU 数据通路                                      │
│                                                                          │
│  ┌────────┐    地址    ┌──────────────┐    数据(指令)    ┌──────────┐   │
│  │   PC   │ ─────────→ │    内存       │ ──────────────→ │    IR    │   │
│  │(程序计数器)│           │  (Memory)    │                 │(指令寄存器)│   │
│  └────────┘           └──────┬───────┘                 └────┬─────┘   │
│      ↑                         │ 数据(读写)                    │ 字段     │
│      │                         │                              ↓          │
│      │                   ┌─────▼──────┐              ┌──────────────┐   │
│      │                   │  寄存器堆    │              │   译码器 ID   │   │
│      │                   │ (Register)  │              │              │   │
│      │                   │ r0~r7 + PC  │              │ 查opcode表   │   │
│      │                   └──┬───────┬──┘              └──────┬───────┘   │
│      │                      │ 操作数A│ 操作数B                 │ 控制信号  │
│      │                      ↓        ↓                        ↓          │
│      │                   ┌──────────────────┐                         │   │
│      │                   │      ALU          │ ◄───────────────────────┘   │
│      │                   │ (算术逻辑单元)     │                             │
│      │                   │  A + B = 结果     │                             │
│      │                   └────────┬─────────┘                             │
│      │                            │ 结果                                    │
│      └────────────────────────────┘（写回 rd）                             │
│                                                                          │
└──────────────────────────────────────────────────────────────────────────┘
```

以 `add t2, t0, t1` 为例的数据流向：
1. PC=0x0008 → 地址总线 → 内存读出 0x074A0000 → IR
2. IR → 译码器提取 opcode=1(ADD), rd=6, rs1=4, rs2=5 → 产生控制信号
3. 寄存器堆：rs1=4 → 读出 t0=1（操作数A），rs2=5 → 读出 t1=2（操作数B）
4. ALU：1 + 2 = 3（结果）
5. 结果写回 rd=6 → t2=3

### 2.8 流水线技术简介（拓展内容）

本教学机采用串行执行，每条指令需要 2 个周期（取指 1 + 执行 1）。真实 CPU 采用**流水线（Pipeline）**技术，将指令执行过程重叠，提高吞吐量。

#### 2.8.1 五级流水线

经典的五级流水线：取指(IF) → 译码(ID) → 执行(EX) → 访存(MEM) → 写回(WB)

```
时间 →  C1   C2   C3   C4   C5   C6   C7   C8   C9
       │    │    │    │    │    │    │    │    │
指令1  IF   ID   EX   MEM  WB  │    │    │    │
指令2  │    IF   ID   EX   MEM  WB  │    │    │
指令3  │    │    IF   ID   EX   MEM  WB  │    │
指令4  │    │    │    IF   ID   EX   MEM  WB  │
指令5  │    │    │    │    IF   ID   EX   MEM  WB
```

理想情况下，每个时钟周期完成一条指令，CPI ≈ 1.0。

#### 2.8.2 流水线冒险（Hazard）

- **结构冒险**：硬件资源冲突（如指令和数据共享内存）
- **数据冒险**：指令间数据依赖（如 add 的结果被下一条指令使用）
- **控制冒险**：分支指令改变 PC（如 beq/jal）

解决方案：转发（Forwarding）、停顿（Stall）、分支预测（Branch Prediction）、乱序执行。

### 2.9 CPU 性能指标

| 指标 | 含义 | 本教学机 |
|------|------|---------|
| 字长 | ALU 一次能处理的二进制位数 | 32 位 |
| 主频 | 每秒时钟周期数 | （模拟，无实际主频） |
| CPI | 每条指令平均时钟周期数 | 2.0（串行执行） |
| 内存容量 | 内存总字节数 | 1024 字节（1KB） |
| 指令数 | 程序包含的指令数 | x=1+2 程序：3 条 |
| 总周期数 | 执行程序需要的时钟周期数 | x=1+2 程序：6 个 |

**CPU 执行时间公式**：
$$T_{CPU} = \frac{指令数 × CPI}{时钟频率}$$

## 七、常见问题与解答

**Q1：为什么 r0 恒为 0？写 r0 会怎样？**

A：r0（zero）硬连线为 0，读 r0 永远返回 0，写 r0 被忽略。这是 RISC-V 的经典设计——用一个寄存器换取多种伪指令（nop、li、mv、j、bnez 等）。

**Q2：为什么指令长度固定为 32 位？变长指令有什么问题？**

A：固定长度指令简化了取指逻辑——PC 每次 +4，不需要先判断指令长度再决定下一条指令的地址。变长指令（如 x86）虽然代码密度高，但取指和译码复杂，不利于流水线。

**Q3：小端序和大端序哪个更好？**

A：没有绝对的好坏。小端序的好处是类型转换方便（低字节在低地址），x86、RISC-V 默认用小端序。大端序的好处是符号位在低地址，便于判断正负，网络字节序用大端序。本教学机采用小端序。

**Q4：为什么本实验的 CPI 是 2.0？真实 CPU 的 CPI 是多少？**

A：本教学机采用串行执行，每条指令需要取指 1 个周期 + 执行 1 个周期，所以 CPI=2.0。真实 CPU 采用流水线技术，理想 CPI≈1.0，实际由于流水线冒险，CPI 通常在 1.0-2.0 之间。超标量 CPU 每个周期可以执行多条指令，CPI 可以小于 1（即 IPC > 1）。

**Q5：ecall 是什么？为什么需要系统调用？**

A：ecall（environment call）是 RISC-V 的环境调用指令，用于从用户态陷入内核态，请求操作系统服务。本教学机简化了特权级，ecall 直接由模拟器处理，实现 print_int（输出整数）和 exit（程序退出）两个系统调用。真实系统中，系统调用是用户程序访问硬件和操作系统服务的唯一接口。

**Q6：如果程序中有无限循环，模拟器会怎样？**

A：模拟器设置了最大周期数（默认 100000），超过后会自动停止并提示"可能存在无限循环"。你可以在代码中修改 `MAX_CYCLES` 来调整上限。
